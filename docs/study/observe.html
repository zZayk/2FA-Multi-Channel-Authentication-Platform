🔭 Observe Behaviour

Where to look when you want to see what the system is doing.

1 · Swagger — poke the API by hand

http://localhost:8000/docs   # dev only

Click Authorize, paste your l2t_... key, then try the endpoints live. Every route, schema, and status code is documented there.

2 · Logs — structured JSON, traceable

docker compose logs -f api       # request side
docker compose logs -f worker    # dispatch / send side
docker compose logs -f beat      # scheduler

Logs are JSON. Each OTP carries a correlation_id — grab it from the API log, grep the worker log for the same id, and follow one request across processes:

docker compose logs worker | Select-String "b81d2f6a"

3 · Database — the source of truth

docker compose exec db psql -U app -d app
-- inside psql:
SELECT id, channel, recipient, status, attempt_count, expires_at
FROM otps ORDER BY created_at DESC LIMIT 5;

SELECT name, key_prefix, last_used_at, revoked_at FROM api_keys;

Watch a row move pending → sent after the worker runs, or → verified after a correct verify.

4 · Redis — the job queue

docker compose exec redis redis-cli
# inside redis-cli:
SELECT 1            # broker DB
KEYS *              # celery keys
LLEN celery         # pending job count

5 · See Email codes (optional MailHog)

Add to docker-compose.override.yml, set EMAIL_HOST=mailhog / EMAIL_PORT=1025, then open the inbox UI:

mailhog:
  image: mailhog/mailhog
  ports: ["1025:1025", "8025:8025"]   # 8025 = web inbox
http://localhost:8025   # every email the app "sends" lands here

Learning checklist — prove each behaviour

  • ☐ Request an OTP → a pending row appears in otps.
  • ☐ Within ~1s → worker log shows a send attempt; row flips to sent (or failed with no gateway).
  • ☐ Verify the correct code → row becomes verified, used_at set.
  • ☐ Verify it again → second attempt fails (single-use proven).
  • ☐ Verify 5 wrong codes → row goes expired, attempt_count=5 (lockout proven).
  • ☐ Call with no X-API-Key → 401. Revoke a key, retry → 401.
  • ☐ Set OTP_TTL_SECONDS=30, wait 31s, verify correct code → fails (TTL proven).
Fastest way to test TTL: drop OTP_TTL_SECONDS to 30 in .env, docker compose up -d to reload, request a code, wait, then verify. No need to sit through 5 minutes.
