🗄️ Data Model

Two tables today. Both store secrets as keyed HMAC — never plaintext.

erDiagram OTPS { uuid id PK string code_hash "HMAC-SHA256 hex 64" enum channel "sms or email" string recipient "phone or email" enum status "pending..blocked" timestamptz created_at timestamptz expires_at timestamptz used_at "null until verified" int attempt_count uuid correlation_id "trace id" } API_KEYS { uuid id PK string name string key_hash "HMAC hex 64 unique" string key_prefix "l2t_xxxx audit" timestamptz created_at timestamptz last_used_at "debounced" timestamptz revoked_at "null means active" }
🔑 Why hash, not encrypt?

Hash is one-way. We never need the original code back — only to check "does this match?". HMAC + SECRET_KEY means a stolen DB is useless without the app's secret.

🧵 correlation_id

One UUID stamped per auth attempt. Rides through API → worker → adapter → logs so you can trace a single OTP across processes.
