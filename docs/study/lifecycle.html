🔄 Request Lifecycle

POST /otp/request — follow one OTP from HTTP call to delivered message. Click the steps.

The full sequence

sequenceDiagram autonumber participant C as Client participant A as FastAPI participant Sec as require_api_key participant Svc as otp_service participant DB as Postgres participant R as Redis participant W as Worker participant Ad as Adapter C->>A: POST /otp/request + X-API-Key A->>Sec: resolve dependency Sec->>DB: lookup key by hash, not revoked DB-->>Sec: key row or none then 401 A->>Svc: create_otp(channel, recipient) Svc->>Svc: code = randbelow, hash = HMAC(code) Svc->>DB: INSERT otp PENDING, expires_at Svc-->>A: (otp_row, plaintext_code) A->>R: dispatch_otp.delay(otp_id, code) A-->>C: 201 status pending (no code) Note over W: moments later, async W->>R: pull job W->>DB: load OTP, skip if not PENDING W->>W: render_otp(channel, code) W->>Ad: send(recipient, body) Ad-->>W: SendResult ACCEPTED / RETRY / REJECTED W->>DB: UPDATE status SENT or FAILED
Notice step 11: the API returns 201 before the SMS is sent, and the response never contains the code. The code leaves the system only through the chosen channel — that's the whole point of 2FA.
