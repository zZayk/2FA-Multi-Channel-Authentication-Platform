What you built in Month 1

A production-shaped 2FA service that issues one-time codes over SMS & Email, stores them safely, sends them asynchronously, and guards its API with keys.

The one-sentence mental model
A client asks the API for an OTP → the API saves a hashed code to Postgres and drops a job on Redis → a Celery worker picks it up, renders a message, and hands it to a channel adapter (SMS or Email) → later the client submits the code and the API verifies it.

The 6 moving parts

API FastAPI

HTTP boundary. Validates input, checks the API key, calls services. Never touches SMS/SMTP directly.

DB PostgreSQL 15

Source of truth. OTP rows (hashed) + API keys. Schema versioned by Alembic.

Cache/Broker Redis 7

Three jobs: Celery broker, result backend, future rate-limit store.

Worker Celery worker

Runs the slow stuff (send SMS/email) off the request thread, with retries.

Scheduler Celery Beat

Cron-like. Will drive DLR polling in Month 2. Exactly one instance.

Adapters SMS + Email

TunisiaSMS (httpx) & SMTP (aiosmtplib) behind one interface.
