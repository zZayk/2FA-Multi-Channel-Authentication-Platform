How the containers connect. Everything talks over the 2fa-net Docker network.

flowchart TB Client(["Client / curl / Frontend"]) -->|"HTTP + X-API-Key"| API subgraph net["Docker network: 2fa-net"] API["FastAPI · api:8000"] DB[("PostgreSQL 15")] REDIS[("Redis 7")] WORKER["Celery Worker"] BEAT["Celery Beat"] end API -->|"async SQLAlchemy"| DB API -->|"enqueue .delay()"| REDIS WORKER -->|"pull job"| REDIS WORKER -->|"update status"| DB BEAT -->|"schedule tasks"| REDIS WORKER -->|"render + send"| SMS["TunisiaSMS adapter"] WORKER -->|"render + send"| EMAIL["SMTP adapter"] SMS -->|"HTTPS"| TSMS(["TunisiaSMS API"]) EMAIL -->|"SMTP"| MAIL(["Mail server / MailHog"])
Why the split matters. The API answers in milliseconds because it never waits for an SMS to send — it records intent (a DB row) and queues work (Redis). The worker absorbs slowness and flakiness (retries) without blocking any user.

Layered backend (inside the API box)

flowchart LR R["api/ routers"] --> S["services/ business logic"] S --> M["models/ ORM rows"] S --> CH["services/channels adapters"] S --> T["tasks/ celery"] R -.->|depends| SEC["core/security auth"] R -.->|depends| CFG["core/config settings"]
Rule of thumb: dependencies point downward. Routers know services; services know models. Models never import routers. Break that → circular imports + untestable code.
